# No Way to Return to the Bookmark List After Cold-Start Redirect

After last competition was remembered, there is no way to return back to competition
bookmark list.

## Product Owner Notes

### Problem and user goal

When the app cold-starts and a last-viewed competition is remembered, `main()` sets
`initialLocation` to `/competitions/:id`, bypassing the home screen entirely. Because
there is no previous route on the navigator stack, the standard AppBar back button is
absent or non-functional — tapping it either does nothing or exits the app. The user
is stranded on the Competition Detail screen with no route back to the bookmark list
(home screen `/`).

The user's goal is straightforward: reach any competition detail quickly on launch,
but still be able to return to the full bookmark list when needed.

### What the feature must do

When the app starts directly at a Competition Detail screen (because a last-viewed
competition was remembered), the AppBar back button must navigate the user to the
home screen (`/`). The user must never be left without a way back to the bookmark list,
regardless of how deep into the navigation stack they landed on cold start.

The back button must behave identically to the back button already present on
Competition Detail when it is reached normally by tapping a row on the home screen.
No new button, label, or modal is required — the existing AppBar leading back button
is the correct affordance. The fix is purely in how the router handles the initial
location when there is no prior history.

This must not affect the normal navigation path: when the user arrives at Competition
Detail by tapping a row on the home screen, the back button must continue to return
them to the home screen as it does today.

### Screens affected

- **Competition Detail Screen** (`/competitions/:id`) — back navigation must always
  lead to the home screen, whether the screen was reached normally or via the
  cold-start redirect.
- **Home Screen** (`/`) — no changes required; it remains the back destination.

### UX approach

`go_router` supports configuring a parent route so that navigating to a deep route
directly (e.g. `/competitions/:id` as `initialLocation`) still places the home route
(`/`) in the back-stack. The fix should ensure `/` is always an ancestor of
`/competitions/:id` in the route hierarchy, so a back gesture or tap always works.
No new screen, dialog, or visual affordance is needed. The correction is invisible to
the user in the normal flow and provides the expected "back to list" behaviour when
cold-started.

### Related stories

None. The last-viewed competition feature (`8081f50`) that introduced the cold-start
redirect is already merged.

### Relevant mockups

None — no visual changes required.

### Scope estimate

Small — a single focused change to the router configuration (or `initialLocation`
resolution in `main()`) so that the home route is always present as a back-stack
ancestor of the Competition Detail route. Fits in one issue.
